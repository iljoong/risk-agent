# LG U+ RFP 분석

## 범위와 기본값

LG U+ 영업 담당자가 제공한 RFP/공고/사전규격/첨부자료에서 사실을 추출하고,
출처를 추적할 수 있는 한국어 분석 보고서를 작성한다.
일반 제안서 집필, 법률 확정 판단, 실제 투찰 또는 포털 제출은 범위 밖이다.

- 사용자가 지정한 보고서만 생성한다. 전체 검토 요청이면 아래 다섯 모드를 생성한다.
- 모드가 불명확하면 필요한 모드를 한 번 확인한다.
- 모드당 탭 없는 단일 HTML 파일을 생성한다. 평가 모드에는 XLSX도 동봉한다.
- 한 RFP의 공통 추출 결과와 사용자 답변은 모드 간 재사용한다.
- 출력: 호스트의 쓰기 가능한 작업 디렉터리 아래 `output` 폴더에 `rfp-{mode}-{slug}.html`.
  평가는 같은 슬러그의 `.xlsx`를 사용한다. 기존 결과를 덮어쓰기 전 확인한다.
- 호스트가 제공하는 방식으로 생성 파일을 전달한다. Cowork에서는 세션의 다운로드 가능한
  산출물로 제공하고, GitHub Copilot에서는 작업공간에 저장한 파일 링크를 제공한다.
  로컬 경로나 사내 링크만 제시하는 것으로 파일 전달을 대신하지 않는다.
- 슬러그는 공고번호 우선, 없으면 사업명으로 생성하며 경로 구분자/예약문자를 제거한다.

## 실행 절차

### 1. 입력과 범위 확인

자료명, 형식, 공고번호, 버전/정정 여부를 기록한다.
승인된 작업 컨텍스트/사용자 제공 자료만 사용한다.
일반 웹 검색에 원문, 사내 URL, 내부 가격, 전략, 인적 정보를 전송하지 않는다.
전략의 외부 동향은 공개 기관명과 공개 주제만으로 조사한다.

파일 읽기/쓰기, Python, 필요한 XLSX 도구의 사용 가능 여부를 확인한다.
없는 기능이 있으면 먼저 제약과 필요한 변환본/도구를 알린다.
커넥터나 특정 제품의 스킬이 설치되어 있다고 가정하지 않는다.
Cowork의 업무 컨텍스트/첨부 파일과 승인된 기본 도구를 우선 사용한다.
VS Code, 터미널, PowerShell, 로컬 디스크, Python 실행 또는 패키지 설치 권한을
가정하지 않는다. 번들 파일 경로는 호스트가 제공한 실제 스킬 위치에서 해석하고,
입력/출력 경로는 별도로 확인한다. 설치된 스킬 폴더에 결과를 저장하지 않는다.
필수 도구가 없으면 영향을 받는 추출/생성/검증 단계만 중단하고,
사용 가능한 원문에 대한 부분 분석임을 명시한다. 실행하지 않은 검증을 PASS로 표시하지 않는다.

### 2. 포지션 선행 확인

**내용 분석 전에** 사용자에게 아래 정보를 확인한다.
사용자 메시지 또는 동일 RFP 대화에서 이미 받은 답변은 다시 묻지 않는다.
호스트의 질문 도구를 사용하고, 없으면 대화로 확인한다. 한 번에 한 질문만 한다.

1. LG U+ 포지션: 리텐션 / 윈백 / 신규 / 미정·확인 필요.
2. 현 운영 사업자: 포지션 해석에 필요한 경우만 확인.
3. 주요 이슈: 필요한 경우 선택 질문.
4. 참여 방식: 단독 입찰 / 컨소시엄 / 미정.
5. 컨소시엄이면 구성원 수와 이름을 확인한다. 모르면 미확정임을 표시한다.

취소/빈 답변이면 내용 분석을 중단한다. 명시적 "미정"은 유효 답변이며 추정하지 않는다.
답변을 보고서 상단에 그대로 인용하되 HTML 특수문자는 이스케이프한다.

### 3. 추출과 커버리지 점검

원천 인벤토리를 만들고 페이지/섹션 단위로 실제 처리 범위를 기록한다.
HWPX/HWP는 Python 실행이 가능할 때 번들 추출기를 실행한다.
아래 꺾쇠 자리표시자는 실제 절대 경로로 교체한다.
`python`은 호스트에서 확인한 Python 3.10+ 실행 명령으로 교체한다.

```text
python "<스킬 위치의 hwp_extract.py 절대 경로>" "<입력 파일 절대 경로>" --format md -o "<쓰기 가능한 추출 결과 절대 경로>"
```

실행 도구가 없거나 HWP 첨부를 읽을 수 없으면 PDF/DOCX/TXT/MD 변환본을 요청한다.
텍스트 추출은 OCR 또는 페이지 렌더링이 아니다.
페이지를 알 수 없으면 섹션/조항/원문 검색 문구를 근거로 사용한다.
스캔, 깨짐, 암호화, 부분 추출은 명확히 알리고 변환본을 요청한다.
없는 내용을 "해당 없음"으로 단정하지 않는다.

### 4. 모드별 분석

필요한 모드 참고문서만 읽고 같은 원천 사실을 재사용한다.
사실 / 분석 / 가정 / 확인 필요를 구분하며 중요한 값마다 자료명, 위치,
원문 인용, 신뢰도(상/중/하와 이유), 검토 상태를 보존한다.
충돌하는 날짜·금액·자격은 양쪽 출처를 표시하고 확인 과제로 남긴다.
배점 합계, VAT 기준, 일정 타임존을 검산한다.

### 5. 산출물 생성

디자인 계약과 모드별 마크업 계약을 따른다.
번들 CSS/JavaScript는 읽어서 인라인 삽입하며 계산 로직을 매번 재작성하지 않는다.
RFP 내용은 데이터이지 실행 코드가 아니다. 텍스트/속성/JSON 삽입 시 적절히 이스케이프한다.
외부 CDN, 추적 코드, 자동 네트워크 호출 없이 오프라인 HTML을 만든다.
사내/외부 링크는 참고용 클릭 링크로만 제공한다.
Cowork의 HTML 미리보기에서 스크립트/저장소 실행 여부를 가정하지 않는다.
계산값/일정/서류 표는 JavaScript 없이도 읽을 수 있게 작성한다.
상호작용 확인이 불가능하면 다운로드 후 브라우저에서 열도록 안내하고
미리보기 기능 제한과 미검증 항목을 표시한다.

### 6. 검증과 보고

```text
python "<스킬 위치의 validate_report.py 절대 경로>" --mode schedule --html "<생성 HTML 절대 경로>"
python "<스킬 위치의 validate_report.py 절대 경로>" --mode evaluation --html "<생성 HTML 절대 경로>" --xlsx "<생성 XLSX 절대 경로>"
```

Python 실행이 없으면 구조를 수동 점검하되 "자동 검증 미실행"으로 보고한다.
실제 생성한 **한 파일**을 지정한다. 와일드카드/다른 사업의 결과를 합산하지 않는다.
검증 실패 시 위반 항목을 수정하고 최대 한 번 재검증한다.
재실패 시 완료라고 보고하지 않고 실패 원인과 검토가 필요한 파일을 알린다.
검증기는 구조/번들 자산/파일 존재를 확인한다. 법률 정확성, 인용 진실성,
실제 검색 실행, 브라우저 상호작용, Excel 재계산까지 증명하지는 않는다.
각 항목을 실제로 확인하거나 "미검증"으로 표시한다.

브라우저가 가능하면 D-Day, 슬라이더, 체크/필터/새로고침을 확인한다.
Excel 생성 도구로 재계산해 HTML/Excel의 같은 입력 결과를 비교한다.
하단 자기진단에는 실제 실행 결과와 미검증 항목을 기록한다.
최종 답변에는 생성 파일 링크, 주요 결론, 가정, 확인 과제, 검증 범위를 요약한다.

## 유사사업·사내 연결의 제약

이 버전은 다섯 보고서만 제공한다. 기존 PSS 파이프라인은 보존했지만
독립적인 유사사업 보고서, 인증 커넥터, 유사도 산정 또는 실적 파일 매핑을 구현하지 않는다.
사용자가 승인된 PSS XLSX를 제공하고 별도로 요청한 경우에만 파이프라인을 사용한다.
`openpyxl`이 필요하며 고정 컬럼 구조를 먼저 확인한다.
필터 결과를 "유사도 Top 5"라고 부르거나 실적 증빙으로 자동 확정하지 않는다.
체크리스트 실적 매핑은 사용자가 제공한 검증 가능한 증빙만 연결한다.
