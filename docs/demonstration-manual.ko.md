## 1. 시연 개요

**대상과 소요 시간:** 현재 구현된 조사 데모를 살펴보는 발표자, 분석가, 이해관계자를 위한 안내입니다. 환경 준비 후 약 15~20분을 예상합니다. 시나리오 문서에 제안된 모든 기능이 아니라, 현재 앱에서 사용할 수 있는 기능을 설명합니다.

**시작 안내 멘트:** "이 워크스페이스는 가상의 조사 사례를 사용합니다. 에이전트는 증거를 정리하고 해석을 비판적으로 검토하며, 수정과 검토 확인은 분석가가 통제합니다. 실제 은행, 사건 관리 시스템, 규제 의사결정 서비스에는 연결되어 있지 않습니다."

### 청중에게 보여 줄 내용

| 구간 | 시간 | 시연 내용 |
|---|---|---|
| 알림 열기와 준비 | 3분 | 알림 목록에서 알림을 열어 조사 질문을 확인한 뒤, 패키지에 포함된 가상 증거를 수집합니다. |
| 증거 확인과 반론 검토 | 4분 | 원천 자료의 제약을 확인하고, 설정된 에이전트에 해석 검토를 요청합니다. |
| 수정과 범위 명확화 | 4분 | 분석가의 수정을 저장하고 제한된 조사 범위 양식을 제출합니다. |
| 검토와 기록 준비 | 4분 | 여섯 단계의 결과를 확인하고 복사 가능한 사건 기록을 준비합니다. |
| 변경과 재방문 | 3분 | 검토 무효화, 변경 이력, 저장된 세션 재열기를 보여 줍니다. |

### 1분 사례 설명

Harbour Components Ltd는 가상의 산업용 부품 도매업체입니다. **CASE-1041**에 표시되는 기존 경보 **ALT-2041**의 원래 자금세탁방지(AML) 우선순위는 **High**입니다. 세 건의 입금 합계는 **GBP 48,000**이며, 첫 입금 **56분** 후 Meridian Supply로 **GBP 45,500**이 출금됩니다. 이는 입금 합계의 **94.79%**입니다.

수취인은 확인 가능한 90일 이력에서 관찰되지 않습니다. 이는 시나리오에 명시된 사실이지, 화면의 거래 행만으로 도출한 결론이나 새로운 거래 관계의 증거가 아닙니다. 정상적인 공급업체 대금 지급이라는 설명도 가능합니다. 송장은 누락되어 있고 이전 사건 자료는 접근이 제한되어 있습니다.

### 시연 경로 선택

**전체 경로:** 2~8절을 진행합니다. 증거 준비는 모델 추론을 사용하지 않지만, 메시지 전송과 조사 범위 양식 제출은 설정된 모델을 호출하므로 비용이 발생할 수 있습니다. 응답 문구, 처리 시간, 제안되는 수정 내용은 보장되지 않습니다.

**추론 없는 경로:** 증거 준비, 원천 자료 확인, 수동 수정, 검토, 변경 이력, 세션 재열기를 사용합니다. 에이전트 프롬프트 전송, 정책 검토 요청, 범위 양식 제출은 생략합니다. 양식은 열어서 보여 준 뒤 취소합니다. 이 경로가 실제 에이전트 분석을 시연하는 것은 아니라고 명확히 안내합니다.

**핵심 구분:** 저장된 수정 사항은 이후 에이전트 대화의 컨텍스트에 반영됩니다. 그러나 다른 모든 단계의 문장이 자동으로 다시 작성되거나 원본 기록이 변경되는 것은 아닙니다. 영향을 받는 단계에는 재검토가 필요하다는 상태가 표시됩니다.

## 2. 실행 환경 준비

### 청중 입장 전 준비

Windows PowerShell에서 저장소 루트를 기준으로 작업합니다. 최초 설치, 잠금 파일 기반 의존성 복원, 모델 설정, 인증은 **README.md**를 따릅니다. 자격 증명을 프롬프트나 시연 자료에 복사하지 않습니다.

업그레이드할 때는 앱의 API와 워커를 중지하고, 시작 시 마이그레이션이 실행되기 전에 설정된 데이터 디렉터리를 백업합니다. 기본 경로는 `.data`입니다. README에 따라 백엔드와 프런트엔드 잠금 파일을 복원합니다. 확장 기능이나 의존성이 바뀌면 API와 워커를 모두 재시작합니다. 두 프로세스의 설정과 데이터 디렉터리가 일치해야 합니다.

전체 경로에서는 추론 권한이 있는 모델을 미리 설정하고 선택합니다. 알림을 열면 해당 알림에 연결된 사건이 하나 생성되고, 다시 열면 같은 사건이 재개되므로 리허설 중 중복 세션이 생기지 않습니다. **New investigation**은 누를 때마다 알림과 연결되지 않은 동일 제목의 CASE-1041 세션을 새로 만들므로 꼭 필요할 때만 사용합니다.

### 세 프로세스 실행

**터미널 1 - API**

```powershell
.\.venv\Scripts\python.exe -m uvicorn skill_chat.api.app:create_app --factory --host 127.0.0.1 --port 8000
```

**터미널 2 - 영속 작업 워커**

```powershell
.\.venv\Scripts\python.exe -m skill_chat.tasks.worker
```

**터미널 3 - 프런트엔드**

```powershell
npm --prefix .\web run dev -- --host 127.0.0.1 --port 5173
```

**http://127.0.0.1:5173**을 엽니다. 설정된 프런트엔드 오리진과 정확히 일치하는 주소를 사용합니다. 포트가 이미 사용 중이면 알 수 없는 프로세스를 중지하지 말고 README의 대체 포트 설정을 따릅니다.

### 준비 상태 확인

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health/live
Invoke-RestMethod http://127.0.0.1:8000/health/ready
```

준비 상태에는 최근 워커 하트비트가 필요합니다. 이 확인만으로 클라우드 권한이나 모델 응답 품질이 검증되지는 않습니다. 전체 경로를 발표하기 전 짧은 모델 요청을 별도로 리허설합니다. 이 요청에도 비용이 발생할 수 있습니다.

**발표자 점검표:** 가상 데이터만 사용하고, 청중이 보기 좋게 브라우저를 확대하며, 모델 선택기의 위치를 확인합니다. 진단을 위해 API와 워커 터미널을 준비하되 로그나 비밀 정보가 화면에 노출되지 않도록 합니다. 위의 일반 앱 주소를 사용합니다. `?prototype=centered-chat`으로 여는 메모리 전용 레이아웃 비교 화면이나 격리된 자동 테스트 서버를 실제 앱 대신 사용하지 않습니다.

## 3. 조사 화면 열기와 증거 확인

### 알림 열기

1. 사이드바의 **Alerts (fictional demo)** 목록에서 네 개의 알림을 확인합니다. 각 행에는 알림 ID, 우선순위, 대상, 트리거와 함께 **No case yet. Review by** 날짜 또는 **Case open at** 단계가 표시됩니다. 검토 기한(review-by) 날짜는 알림용일 뿐 규제 자문이 아닙니다.
2. **Open alert ALT-2041, Harbour Components Ltd**를 선택합니다. 이 알림에 연결된 사건이 하나 생성됩니다. 같은 알림을 나중에 다시 선택하면(버튼이 **Resume alert**로 표시됨) 중복 생성 없이 기존 사건이 열립니다.
3. **CASE-1041 evidence desk**, **Demo connector / fictional records**, 원래 경보 우선순위 **High**를 확인합니다. 아직 아무것도 준비되지 않았습니다. 화면에 시작 질문 **Question to answer**가 표시되고 증거가 수집되지 않았다는 안내가 나옵니다.
4. 여섯 단계인 Detect, Investigate, Gather evidence, Analyze, Human review, Decision을 소개합니다. 사건은 **Investigate**에서 시작됩니다. **Detect**를 눌러 **Read-only** 상태임을 보여 줍니다. 원래 알림과 우선순위를 기록하고, 확인 완료 상태로 시작하며, 이후 변경으로 무효화되지 않고, 수정할 수 없습니다. **Continue to Investigate**로 작업 단계로 돌아갑니다.
5. 증거를 준비하기 전에 필요하면 **Clarify investigation scope**를 사용합니다(5장).
6. **Prepare investigation**을 누릅니다. 준비 작업이 성공하고 **Refresh demo evidence**가 활성화될 때까지 기다립니다.

**예상 결과:** 단계별 결과가 갱신됩니다. 중앙의 **Evidence** 탭을 선택하면 거래 타임라인과 증거 목록이 채워져 있습니다. 준비 작업은 백엔드 워커가 패키지에 포함된 가상 기록을 가져오는 과정이며 모델 추론을 사용하지 않습니다. 실제 금융 시스템을 조회하는 것은 아닙니다.

**증거가 없는 알림(선택, 2분):** **ALT-2038** 같은 다른 알림을 열고 **Prepare investigation**을 누릅니다. 패키지 증거는 ALT-2041에만 있으므로, 준비 결과는 누락된 출처 하나(**SRC-00**)와 공백 **GAP-01**을 기록하고 Analyze는 결론을 낼 수 없다고 표시합니다. 증거를 지어내지 않고 공백을 보고한다는 점을 보여 줍니다.

**의뢰 경로:** **New investigation**은 알림 목록 아래에 남아 있으며 의뢰나 수동 단서용입니다. 알림과 연결되지 않은 독립 CASE-1041 세션을 만들고, 이 세션의 Detect 단계는 계속 편집할 수 있습니다.

### 화면 구성과 이동 설명

구현된 **A 레이아웃**은 왼쪽의 **Investigation sessions**, 중앙의 워크플로 및 단계 작업 영역, 오른쪽의 대화와 입력창이 있는 **Investigation assistant**로 구성됩니다.

| 영역 또는 조작부 | 발표자 조작 |
|---|---|
| **Output** 탭 | 선택한 단계의 결과, 공유 사실, 변경 이력을 확인하거나 수정합니다. |
| **Evidence** 탭 | 거래 타임라인, 증거 목록, 원천 기록을 확인합니다. |
| **Review** 탭 | 분석가 판단 근거를 입력하고 기록을 검토·준비·복사합니다. **Review & record**도 이 탭을 엽니다. |
| 사이드바 경계선 | 데스크톱에서 양쪽 경계선을 드래그합니다. 키보드로 포커스를 준 뒤 좌우 화살표로 조절할 수 있고, Home/End는 최소·최대 너비를 선택합니다. |
| **Chat** | 오른쪽 대화 사이드바를 열거나 닫습니다. 사이드바의 닫기 아이콘으로 작업 영역으로 돌아가도 작성 중인 메시지는 유지됩니다. |
| 해·달 아이콘 버튼 | 라이트·다크 모드를 전환합니다. 첫 방문에는 시스템 설정을 따르며, 브라우저 저장소를 사용할 수 있으면 직접 선택한 모드가 저장됩니다. |

화면 너비가 1,000픽셀 이하이면 세션 목록과 채팅은 동시에 나란히 표시되는 열이 아니라 열고 닫는 패널로 동작하고, 너비 조절 핸들은 숨겨집니다. **Toggle history**로 세션 목록을 열고 **Chat**으로 에이전트를 엽니다. 중앙 작업 영역을 편집할 때는 먼저 채팅 패널을 닫습니다.

**Analyze**를 누르면 해당 단계의 **Output** 탭이 열립니다. 어떤 단계를 선택해도 Output으로 돌아오지만, 현재 워크플로 단계가 자동으로 진행되지는 않습니다. 현재 단계를 의도적으로 바꿀 때만 **Make current stage**를 사용합니다. 이후 기록 검토는 현재 단계를 Human review로, 기록 준비는 Decision으로 설정합니다.

### 원천 기록 확인

**Evidence**를 선택한 뒤 관련 증거 항목의 **Inspect SRC-01**을 엽니다. 선택된 원장 기록, 가상 데이터 스냅샷, 버전, 조회 시각, 자료 범위를 확인합니다. 다음 항목으로 이동하기 전에 **Close source**를 누릅니다.

| 기록 | UTC 시각 | 금액 | 거래 상대방 |
|---|---|---|---|
| TX-781 | 09:12 | +GBP 18,000 | Alder Industrial |
| TX-782 | 09:31 | +GBP 16,000 | Beacon Assembly |
| TX-783 | 09:54 | +GBP 14,000 | Cedar Parts |
| TX-784 | 10:08 | -GBP 45,500 | Meridian Supply |

**Analyze**를 선택하여 **Output**으로 돌아온 뒤 94.79% 비교 수치와 56분 구간을 짚어 줍니다. 선택된 기록에는 잔액이 없으며, 자금의 실제 연결 관계나 의도를 입증하지 않는다고 설명합니다.

**Evidence**로 돌아갑니다. **SRC-04**를 확인하여 이전 사건의 접근 제한을 보여 주고, **SRC-07**을 확인하여 송장 누락을 보여 줍니다. **All sources (7)**에서도 각 원천 자료를 열 수 있습니다.

**예상 결과:** SRC-04는 계속 접근 제한 상태이고 SRC-07은 계속 누락 상태입니다. 어느 상태도 불리한 사실이 확인되었다거나 증빙 대조를 완료했다는 뜻이 아닙니다. 증거를 새로고침하면 조회 정보는 바뀔 수 있지만, 접근할 수 없던 기록이 열리거나 오래된 가상 자료의 내용이 최신화되는 것은 아닙니다.

**설명 멘트:** "원천 자료의 최신성과 조회 시각은 다릅니다. 제공된 자료와 제공되지 않은 자료를 구분하고, 결론의 한계가 무엇인지 확인할 수 있습니다."

## 4. 해석에 반론을 제기하고 수정하기

### 설정된 에이전트에 요청

전체 경로에서는 중앙의 **Analyze**를 선택한 뒤 오른쪽 **Investigation assistant**의 **Draft a challenge**를 누릅니다. 사이드바가 닫혀 있으면 먼저 **Chat**으로 엽니다. 이 버튼은 입력창에 프롬프트를 채울 뿐입니다. 내용을 확인한 뒤 **Send message**를 누릅니다.

새로 생성된 작업이 끝날 때까지 기다립니다. 앞선 작업의 성공 상태를 새 요청의 결과로 혼동하지 않습니다. 고정된 답변을 약속하지 말고 실제 응답과 단계 결과를 확인합니다.

**후속 프롬프트 예시:**

> 우려를 반박하는 증거는 무엇인가요? 관찰된 사실, 검증된 계산 비교, 대안적 설명, 정보 공백을 구분해 주세요. 증거 참조를 포함하여 Analyze 결과의 수정안을 제안해 주세요. 위법행위, 자금의 실제 연결 관계, 접근이 제한된 이전 사건의 내용은 추정하지 마세요.

**예상 동작:** 에이전트는 현재 저장된 조사 컨텍스트를 받고 허용된 범위에서 단계 결과의 수정을 제안할 수 있습니다. 작업이 성공해야 제안이 공식 저장 결과로 반영됩니다. 응답이 나왔다는 이유만으로 단계 결과가 바뀌었다고 간주하지 말고 실제 텍스트와 버전을 확인합니다. 수정 제안이 없으면 명시적으로 요청하거나 아래 수동 수정을 사용합니다.

### 분석가 수정 저장

**Analyze**를 선택하고 **Stage output**을 아래 예시로 바꾼 뒤 수정 이유를 입력합니다.

> 선택된 기록에는 56분 구간에 GBP 48,000의 입금과 GBP 45,500의 출금이 나타납니다 [E-01]. 시간 간격만으로 의도나 자금의 실제 연결 관계를 입증할 수는 없습니다. 공급업체 대금 지급은 사업 특성과 부합할 수 있지만 [E-03], 송장은 검증되지 않았습니다 [E-04, GAP-01]. 접근이 제한된 이전 사건의 내용은 불리한 증거로 취급할 수 없습니다 [GAP-02].

**Reason for stage amendment 예시:**

> 대안적 설명을 유지하고 관찰된 사실과 해석을 구분하기 위함입니다.

저장하기 전에 **Detect**를 선택했다가 **Analyze**로 돌아옵니다. 이어서 **Evidence**로 전환한 뒤 **Output**으로 돌아옵니다. 두 종류의 이동 모두에서 저장 전 결과와 수정 이유가 유지되어야 합니다. **Apply stage amendment**를 눌러 저장합니다.

**예상 결과:** 조사 리비전과 결과 버전이 증가하고, Analyze 및 이후 단계에 재검토가 필요해지며, 준비된 기록은 지워집니다. 이전 단계의 문장이나 원천 기록은 덮어쓰지 않습니다.

### 저장과 임시 보존 구분

저장된 수정 사항은 이후 에이전트 컨텍스트에 포함됩니다. 조사 화면이 열린 동안 저장 전 단계 결과, 수정 이유, 검토 판단 근거는 탭을 바꿔도 유지됩니다. 단계 결과는 다른 단계를 살펴보고 돌아와도 유지됩니다. 작성 중인 메시지는 에이전트 사이드바를 닫았다가 열어도 유지됩니다. 그러나 임시 입력은 저장된 기록이 아니므로 새로고침이나 세션 변경 후에도 남아 있을 것으로 기대해서는 안 됩니다.

**Output**의 **Revision history**에서 수정 내용과 이유를 확인합니다. 제공되는 경우 **Previous text**, **Saved text**를 열고 **Load older revisions**로 이전 이력을 불러옵니다. 이는 앱의 변경 이력이지 외부 컴플라이언스 감사 시스템의 증거는 아닙니다.

> 제공된 가상의 G-AML-07 v3 및 L-01 v2 발췌문을 사용하여, 사람이 사건 종결이나 상향 보고를 권고하기 전에 남아 있는 확인 절차와 정보 공백을 정리해 주세요. 문서 내 위치를 인용해 주세요. 이 데모 정책과 법률을 구분하고, 송장 대조 확인이 완료되었다고 주장하지 마세요.

### 선택 사항: AML 스킬

여섯 워크플로 단계가 여섯 스킬을 자동으로 실행하는 것은 아닙니다. 전체 경로에서 설치된 AML 스킬을 보여 주려면 먼저 증거를 준비하고, 에이전트 입력창의 **Skills**에서 하나를 선택하거나 슬래시 명령을 입력합니다. 선택 팝업에는 설명 없이 이름만 표시됩니다.

| 스킬 | 시연 초점 |
|---|---|
| `/aml-case-context` | 기록된 경보, 고객 배경, 확인이 필요한 정보 공백을 설명합니다. |
| `/aml-transaction-behaviour` | 검증된 거래 지표를 예상 활동 및 이력과 비교하여 평가합니다. |
| `/aml-hypothesis-review` | 우려를 합법적인 대안적 설명 및 반대 증거와 대조합니다. |
| `/aml-policy-applicability` | 제공된 절차의 적용 여부와 사람의 승인 요건을 확인합니다. |
| `/aml-investigation-readiness` | 미완료 확인을 식별합니다. 필수 증거가 없으면 준비 완료로 판단해서는 안 됩니다. |
| `/aml-case-narrative` | 분석가 검토용으로 인용을 포함한 편집 가능한 사건 기록 초안을 작성합니다. |

스킬은 선택적으로 제공되는 지침입니다. 검증된 위험 모델, 실제 은행의 승인된 정책 모음, 계산 엔진, 실시간 사건 연계 기능은 아닙니다. 계산에는 검증된 준비 지표나 식별된 승인 도구의 결과를 사용해야 하며, 언어 모델이 직접 산술 계산을 만들어서는 안 됩니다. 스킬 선택만으로 추론이 시작되지는 않지만 프롬프트를 전송하면 모델을 호출합니다. 선택한 스킬은 후속 대화에도 유지되므로, 일반 프롬프트로 돌아갈 때는 입력창의 스킬 칩에서 **Clear skill**을 누릅니다.

### AG-UI를 과장 없이 설명하기

**AG-UI**는 재생 가능한 조사 상태 스냅샷과 명확화 활동을 고정된 React 워크스페이스에 전달합니다. 사용자 동작은 서버에서 검증되는 명령이며, 대화 텍스트는 기존의 별도 스트림을 유지합니다.

**A2UI**는 제한된 조사 범위 양식만 렌더링합니다. 임의의 에이전트 작성 워크플로 설계, 완전한 AG-UI 텍스트·도구 생명주기 구현, 사람의 입력을 기다리는 워커에 대한 SDK 체크포인트·재개 기능은 아닙니다.

## 6. 검토와 사건 기록 준비

이 구간을 시작하기 전에 에이전트 작업과 수정을 마칩니다. 이후의 중요한 변경은 검토를 무효화할 수 있습니다.

### 사람이 작성하는 단계 결과 채우기

준비 작업은 증거와 분석을 채울 뿐, 사람의 판단을 완성하지 않습니다. 모든 단계를 확인합니다. "Awaiting investigation preparation and human assessment"와 같은 대기 문구를 완성된 평가처럼 승인하지 않습니다.

**Human review** 결과를 시연 상황에 맞게 수정합니다.

> 분석가는 선택된 거래 비교 수치를 확인하고 정상적인 공급업체 대금 지급이라는 설명을 검토했습니다. 송장은 제공되지 않았으며 [GAP-01], 이전 사건 내용은 접근 제한 상태입니다 [GAP-02]. 의도나 자금의 실제 연결 관계에 대한 결론은 입증되지 않았습니다.

**Decision**에는 실행된 결정이 아니라 제안하는 다음 조치를 기록합니다.

> 제안하는 다음 조치: 종결 검토 전에 송장 증빙을 확보하고 이전 사건에 대한 정당한 접근 권한을 요청합니다. 사건 종결, 상향 보고 승인, 규제 신고, 계좌 제한은 실행되지 않았습니다.

각 변경에 의미 있는 **Reason for stage amendment**를 입력하고 **Apply stage amendment**를 누릅니다. 이 예시는 발표자가 제시하는 판단이지 자동 생성된 에이전트의 발견 사항이 아닙니다.

### 결과 확인과 기록 검토

1. 마지막 수정 후 편집 가능한 다섯 단계의 결과를 방문합니다. 알림에서 연 사건의 Detect는 읽기 전용이며 이미 확인된 상태입니다.
2. 각 결과와 증거 참조를 확인합니다. 내용에 동의할 때만 **Acknowledge this output**을 누릅니다.
3. 요청 처리 중 버튼이 비활성화된 상태가 아니라, 편집 가능한 각 단계 표시가 **Acknowledged**로 바뀌었는지 확인합니다.
4. 중앙의 **Review** 탭이나 **Review & record**를 엽니다. **Analyst rationale**에 아래 예시를 실제 결과에 맞게 조정하여 입력합니다.
5. **Mark note reviewed**를 누른 뒤 **Prepare case note**를 누릅니다.

> 선택된 기록과 대안적인 공급업체 대금 지급 설명을 확인했습니다. 송장 공백과 이전 사건 접근 제한은 해결되지 않았습니다. 허용된 추가 증거 수집을 제안하며, 외부 의사결정이나 승인은 확인되지 않았습니다.

**예상 결과:** 증거 준비가 성공했어야 하고, 영향을 받는 모든 결과가 확인되어야 하며, 판단 근거가 비어 있지 않아야 합니다. 준비된 기록에는 공유 사실, 단계 결과, 판단 근거, 수집된 증거에 기반한 참조와 공백, **External saving / approval: unconfirmed**가 표시됩니다.

### 복사를 외부 처리 완료로 표현하지 않기

**Copy case note**를 누릅니다. 클립보드 접근이 불가능하면 표시된 기록을 직접 선택하여 복사합니다. 실제 사건 시스템이 아니라 폐기 가능한 시연 문서에 붙여 넣습니다.

**설명 멘트:** "기존의 사람 중심 업무 절차에서 사용할 기록을 준비한 것입니다. 복사는 외부 시스템 저장, 조치 승인, 사건 종결을 뜻하지 않습니다."

## 7. 변경에 따른 검토 무효화 보여 주기

### 공유 사실 수정

기록을 준비한 뒤 **Output**을 선택하고 **Shared fact across all stages**를 엽니다. **Shared beneficiary description**을 다음과 같이 바꿉니다.

> Meridian Supply는 확인 가능한 90일 이력에서 관찰되지 않았으며, 상업적 거래 관계가 언제 시작되었는지는 알 수 없습니다.

**Reason for shared fact amendment**에는 다음과 같이 입력합니다.

> 확인 가능한 이력에 없다는 사실을 새로운 거래 관계와 동일시하지 않기 위함입니다.

**Apply shared fact amendment**를 누릅니다.

**예상 결과:** 공유 사실이 바뀌고, 편집 가능한 다섯 결과에 재검토가 필요해지며(알림에서 연 사건의 Detect는 확인 상태 유지), 검토 완료 표시와 준비된 기록이 지워집니다. **Review**로 돌아가면 **Copy case note**를 사용할 수 없고, 필요한 결과 확인을 다시 마칠 때까지 기록 검토가 차단됩니다. Output으로 탭만 바꾼 것은 기록을 숨길 뿐이며, 실제 무효화는 수정 저장 때문에 발생합니다.

변경된 공유 문구는 이후 에이전트 대화에서 사용할 수 있습니다. 각 단계 텍스트가 자동으로 교체되거나 변경 불가능한 원천 내용이 바뀌지는 않습니다. 에이전트 반영을 시연하려면 수정된 공유 사실을 설명하고 필요한 결과 수정을 제안하도록 짧게 요청합니다. 이는 모델 호출입니다.

### 이력 확인과 세션 재열기

**Output**으로 돌아가 **Revision history**를 엽니다. 변경의 수행 주체, 동작, 리비전, 이유, 변경 전후 텍스트를 보여 줍니다. 가능하면 이전 이력을 추가로 불러옵니다.

남은 초안은 저장한 뒤 페이지를 새로고침합니다. 사이드바의 알림 목록에서 **Resume alert ALT-2041**을 선택하거나 **Investigation sessions**에서 사건을 다시 엽니다. 같은 제목이 여러 개면 방금 사용한 세션을 선택합니다. 저장된 수정, 증거, 범위 명확화 상태가 유지되는지 확인합니다.

새로고침만으로 증거 준비나 에이전트 분석이 다시 실행되지는 않습니다. 브라우저 연결이 끊겨도 영속 백그라운드 작업은 취소되지 않습니다.

### 일반 대화와 구분

**New conversation**을 선택하여 일반 대화, PDF 검토, 선택적 스킬, 저장된 HTML 결과물을 계속 사용할 수 있음을 보여 줍니다. 삭제된 과거 RFP 스킬을 현재 제품 기능으로 소개하지 않습니다.

**마무리 멘트:** "저장과 편집이 가능하고 변경 이력을 확인할 수 있는 증거 검토 워크스페이스를 살펴봤습니다. 분석가는 에이전트에 반론을 요청하고 내용을 수정할 수 있습니다. 원천 자료의 한계는 계속 드러나며, 앱이 중대한 금융·규제 의사결정을 실행하지는 않습니다."

### 다음 시연을 위한 초기화

다른 알림(예: ALT-2036)을 열거나 **New investigation**으로 독립된 새 가상 세션을 만듭니다. ALT-2041을 다시 열면 기존 사건이 재개될 뿐 초기화되지 않습니다. ALT-2041을 처음부터 반복하려면 **Investigation sessions**에서 해당 세션을 삭제합니다(알림이 새 사건에 다시 사용 가능해집니다). 초기화를 위해 `.data`를 삭제하지 않습니다. **Refresh demo evidence**를 초기화 버튼처럼 사용하지 않습니다. 새 준비 작업이 생성되고 이전 검토가 무효화될 수 있습니다.

## 8. 문제 해결과 운영 경계

| 증상 | 발표자 대응 |
|---|---|
| 작업이 계속 대기 중 | 워커 준비 상태와 API·워커의 설정 일치를 확인합니다. 요청을 중복 제출하지 않습니다. |
| 조작 버튼이 비활성화됨 | 실행 중인 대화나 변경 처리가 끝날 때까지 기다립니다. 검토에는 증거 준비, 결과 확인, 판단 근거도 필요합니다. |
| 리비전 충돌 | 로컬 초안을 보존하고 저장된 결과와 비교합니다. 제공되는 경우 **Keep draft and use latest revision**을 선택한 뒤 이유와 함께 의도적으로 재적용합니다. 다른 리비전을 무조건 덮어쓰지 않습니다. |
| 모델 실패 또는 권한 없음 | 실패 상태를 숨기지 않습니다. 발표 밖에서 공급자 설정을 확인하거나 추론 없는 경로로 전환합니다. 가상 고정 응답을 실시간 추론이라고 설명하지 않습니다. |
| 컨텍스트 예산 초과 | 과도하게 긴 저장 결과를 줄이거나 적절한 예산이 설정된 모델을 선택합니다. 재시도가 오래된 분석을 자동으로 최신 상태에 맞추지는 않습니다. |
| 자료가 계속 접근 불가 | SRC-04는 접근 제한, SRC-07은 누락 상태로 설계되었다고 설명합니다. 접근 우회나 송장 조회 성공을 암시하지 않습니다. |
| 기록 준비 불가 | 증거 준비를 마치고, 대기 문구를 수정하고, 영향을 받는 모든 단계를 확인하고, 판단 근거를 입력한 뒤 기록을 검토 완료로 표시합니다. |
| 범위 양식 렌더링 실패 | 제공되는 일반 양식 대체 화면을 사용합니다. 양식 자체가 유효하지 않으면 세션을 다시 열어 불러옵니다. |
| 복사 실패 | 표시된 기록을 직접 선택하여 복사합니다. 외부 저장은 여전히 확인되지 않은 상태입니다. |
| 세션 목록 또는 에이전트가 숨겨짐 | 세션은 **Toggle history**, 에이전트는 **Chat**으로 엽니다. 좁은 화면에서 중앙 영역을 편집하려면 먼저 채팅 패널을 닫습니다. |
| 타임라인·검토·이력이 안 보임 | 자료는 **Evidence**, 기록은 **Review**, 공유 사실과 변경 이력은 **Output**에 있습니다. 단계를 선택하면 Output으로 돌아갑니다. |

### 정확히 설명해야 할 운영 한계

앱은 로컬 단일 사용자용입니다. API 프로세스 한 개, 워커 한 개, 전체에서 실행 중인 작업 한 개, 세션별 활성 대화 한 개를 지원합니다. 로컬 범위 식별자는 다중 사용자 인증이 아닙니다. 청중에게 공개 배포하기 위해 루프백·오리진 보호를 완화하지 않습니다.

**Stop**은 협조적 취소 요청입니다. 최종 상태를 확인할 때까지 기다립니다. **Retry**는 명시적인 재시도이며 이전 작업과 연결된 새 작업을 만듭니다. 실패·취소되었거나 오래된 상태에 기반한 제안을 게시된 결과로 설명해서는 안 됩니다. 브라우저를 닫는 것은 취소가 아닙니다.

이 데모는 실시간 이상 거래 탐지, 검증된 위험 점수 계산, 규제 준수 입증, 실제 은행·사건 시스템 연결을 제공하지 않습니다. 변경 이력이 완전한 규제 감사 통제 구현을 의미하지도 않습니다. 시나리오에 있는 알림 목록은 패키지에 포함된 가상 알림 네 건뿐입니다. 실시간 피드, 담당자 배정, 분류(triage) 기록, "사건 불필요" 처리는 없으며 검토 기한 날짜는 알림용일 뿐입니다. 고급 필터와 전체 운영 모델 등 다른 시나리오 기능도 모두 구현된 것은 아닙니다.

현재 조합의 공식 A2UI 패키지에는 상위 Zod 의존성 권고 **GHSA-mrhx-c7xc-m3w5**가 남아 있습니다. 고정 템플릿 검증과 크기·깊이 제한은 보호 조치이지, 해당 권고가 해결되었다는 주장은 아닙니다. 의존성 고지는 README를 참고합니다.
