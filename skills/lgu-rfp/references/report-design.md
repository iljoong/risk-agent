# HTML 디자인과 검증 계약

## 공통

- UTF-8, `lang="ko"`, viewport, 사업명 title, 탭 없는 단일 페이지.
- `<section class="page-panel" id="{mode}">`로 보고서 본문을 감싼다.
- 흰 카드/뉴트럴 배경, 마젠타는 버튼·링크·제목 테두리 등 포인트만 사용.
  본문 전체 마젠타 배경 금지. 위험도 상=빨강, 중=앰버, 하=초록.
- 표는 `<thead>/<tbody>/<th>`를 사용하고 근거는 `<details>`/각주로 표시.
- 기업 판정, 사용자 포지션/참여 방식, 원천 인벤토리, 커버리지 선언을 포함.
- 공통 CSS는 번들 `assets\report.css`를 인라인 삽입.
- `<details id="diagnostics"><summary>자기진단 로그</summary>…</details>`를 하단에 포함.
  실제 명령 결과, 검증 시각, 스킬 버전, 미검증 항목을 기록. 예시 PASS를 그대로 복사하지 않는다.
- 텍스트/속성값은 이스케이프한다. 사용자 입력을 `innerHTML`에 넣지 않는다.
- 생성 시 외부 스크립트/스타일/폰트 다운로드를 포함하지 않는다.
- 필수 UI에는 읽을 수 있는 라벨, 키보드 조작, 오류 영역을 제공한다.
- Cowork 미리보기의 JavaScript 실행/저장소를 전제하지 않는다.
  일정·가격 구간표·서류 목록은 스크립트 없이도 읽을 수 있는 실제 값으로 채운다.
  상호작용 미검증 시 다운로드 후 브라우저 확인 안내를 표시한다.

## 자산 삽입

번들 파일을 읽어서 `<script data-asset="dday.js">…</script>`처럼 삽입한다.
평가에는 `price-engine.js`, 체크리스트에는 `checklist.js`를 사용한다.
검증기는 실제 번들 내용과 비교하므로 임의 수정/다른 로직 삽입은 통과하지 않는다.
초기화는 DOM 준비 후 한 번, 계산은 입력 변화마다 수행한다.
IIFE 개수/공백은 품질 지표가 아니다. 누락 요소/잘못된 입력/저장 실패를
사용자 오류 영역과 개발자 콘솔에 표시한다.

## 검증 범위

검증기는 Python 표준 라이브러리만 사용한다.

| 모드 | 구조 검증 |
|---|---|
| 공통 | UTF-8 선언, 본문, 인벤토리, 커버리지/경고, 진단, 고유 HTML ID |
| overview | 27개 고유 필드, 참가자격 7개 하위 필드, 연락처 5개 하위 필드 |
| schedule | 12개 고유 일정, 마감값/확인 필요 경고, D-Day 번들 |
| evaluation | 산식 상태/라벨, 유효 상수/임계값, 가격 번들 또는 미지원 경고, XLSX 링크/시트 |
| strategy | 6컬럼 리스크 표, 6개 동향 블록, 공개 출처 또는 정보 제약 표시 |
| checklist | 45+ 기준 행, 단계/요구분류/근거, 행별 고유 체크박스/상태, 구성원사별 항목, 참고 링크 |

정확한 검증용 ID/속성은 각 모드 참고문서에 정의한다.
행 수는 헤더를 제외한 실제 행을 센다. 행에 키워드를 반복해 통과시키지 않는다.
검증기는 인용/법률/기업 자격/공개 뉴스의 사실 여부, OCR 품질, 실제 웹 검색,
브라우저 이벤트 또는 Excel 수식 평가를 판정하지 않는다.

### 기능 확인

- 일정: KST 당일/전일/경과 마감, 날짜 없는 경우 경고.
- 평가: 상한·하한과 ±1% 경계, 입력 범위 밖/빈 입력, HTML/XLSX 결과 일치.
- 체크리스트: 직접 체크/행 클릭, 완료 배지/진행률, 단계별 진행률,
  필터 상태에서 체크/해제, 새로고침 복원, 전체 해제,
  저장소 접근 불가/손상 데이터 경고.
- 재검증은 실패 원인을 수정한 후 최대 한 번. 계속 실패하면 미완료로 보고.
