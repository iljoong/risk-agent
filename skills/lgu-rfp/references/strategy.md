# 유불리·독소 조항·전략 모드

출력: `output\rfp-strategy-{slug}.html`.
사용자 포지션/운영사업자/이슈를 상단에 인용한다.

## 원문 기반 분석

- 유리/중립/불리 총평에 원문 근거 최소 3개를 목표로 한다.
  원문이 부족하면 근거 부족을 표시하고 채우기 위해 창작하지 않는다.
- 사전규격/의견서/이전 질의 응답/댓글/변경 이력이 제공되면 우선 검토한다.
  실제 확인한 변경을 총평/리스크 대응에 반영하고 본문과 충돌 시 양쪽 인용을 남긴다.
- 특정 벤더/인증/실적/스택 제한, 과도 인력/SLA/납기/보증,
  일방 책임/모호 검수/무제한 지원, 모호 기술, 제출 행정 리스크를 점검한다.
- `id="personnel-risks"`에 상주인력의 수/기간/장소/자격과
  제안PM-이행PM 동일성의 강도/변경 제한/패널티를 별도로 표시한다.
- 조항 미발견은 "제공된 검토 범위에서 미확인"으로 쓰고 원문 완전성에 맞춰 표현한다.
- 불허 문구가 있어도 승인/예외/반대 조항을 재검색하고 함께 제시한다.

`<table id="risk-table">`은 정확히 아래 6개 헤더와 각 행의 6개 셀을 갖는다.

1. 위험도
2. 원문 조항 + 위치
3. 문제 설명
4. 영향
5. 대응 방향
6. 의견서·질의 초안

영향은 점수/기간/원가로 정량화하되 계산 근거가 없으면 정성 설명/확인 필요로 남긴다.
질의 초안은 정중한 공문체 1~2문장(가능하면 80자 이내).
별도 질의가 필요 없으면 "현행 유지 의견 — 별도 질의 불필요".
위법이라고 확정하지 않고 경쟁 제한 가능성/법무 검토 필요를 표시한다.
리스크가 없으면 6셀의 "검토 범위에서 추가 리스크 미확인" 행을 둔다.

## 공개 고객 동향

RFP/사내자료와 분리해 `id="customer-trends"`에 공개 정보 라벨을 붙인다.
공개 기관명/약칭/영문명/상위기관을 확인하고 다음 주제를 조사한다.
CEO 메시지, 중장기 전략, 핵심사업, DX/AI/클라우드, 보안/인프라,
최근 뉴스, 정책/예산, 조직개편/인사.
공식 기관/정부 채널 우선. 뉴스는 최근 6개월, 나머지는 최근 12개월을 우선한다.
각 출처의 날짜/URL과 실제 조사 범위를 기록한다.
검색 횟수/URL 개수는 품질 증거가 아니므로 기존 "최소 6회" 강제를 제거한다.
사내 내용을 검색 쿼리에 포함하지 않는다.

아래 여섯 `<section data-trend="B-1">` 등 블록은 항상 유지한다.

| 블록 | 목표 내용 |
|---|---|
| B-1 | 공식 메시지 2~3개 짧은 인용, 의미 단위 키워드 5~8개 |
| B-2 | 추진사업 3~5개: 목표/예산·규모/RFP 연관성/출처 |
| B-3 | 최근 이슈 4~6개: 날짜 역순/요약/영향/출처 |
| B-4 | RFP 요건 5~8개 × 고객 관심영역(목표 5×3+) 매트릭스, 매칭 인사이트 |
| B-5 | 제안 메시지 3~5개: 슬로건/본문/동향-RFP 연결 근거/출처 |
| B-6 | 역풍 신호: 우려/영향/대응/출처 |

각 블록의 사실에는 실제 공개 출처 링크를 넣는다.
도구 불가/비공개/정보 부족이면 해당 블록에 `class="research-unavailable"`인
"확인 필요 — 공개 정보 조사 불가/부족"을 넣고 생략/창작하지 않는다.
상위기관 동향을 쓰면 고객사 자체 정보와 구분해 대체 사실을 명시한다.

## 의견서와 차별화

사전규격이면 의견서 초안을 제공한다:
제목/인사/대상 조항과 위치/검토 의견/기존 vs 제안 수정안/기대 효과.
최종 제출 전 사용자/법무 검토 필요를 표시한다.

`id="differentiation"`에 기술적 메시지와 상업·운영·리스크 메시지를 각각
슬로건 1줄 + 설명 2~4줄로 제공한다.
리텐션이면 검증 가능한 기존 사업자 근거로 전략 2개를 목표로 한다.
공개 고객 관심사와 연결하되 확인하지 못한 CEO 키워드를 붙이지 않는다.
